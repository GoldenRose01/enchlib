# EnchLib v1.0.1 – Note di rilascio

EnchLib 1.0.1 è una release di transizione focalizzata sull'aggiornamento a Minecraft 26.1.2 e sull'introduzione di un sistema di configurazione completamente basato su file JSON5.

## 🔄 Differenze principali rispetto alla v1.0.0

### Aggiornamento tecnico
- Target aggiornato a Minecraft `26.1.2`, Fabric Loader `0.19.2`, Fabric API `0.148.0+26.1.2` e Java `25`.
- Toolchain aggiornata a Fabric Loom `1.16-SNAPSHOT` con plugin `net.fabricmc.fabric-loom`, Gradle `9.4.0`, Kotlin `2.3.21` e Fabric Language Kotlin `1.13.11+kotlin.2.3.21`.
- Rimosso il riferimento a Yarn mappings dal build script perché Minecraft 26.1.x usa il flusso Fabric non-remapping.
- Migrazione agli strumenti Brigadier moderni tramite `RegistryEntryReferenceArgumentType`.
- Uso della riflessione sugli `ItemEnchantmentsComponent` per garantire compatibilità con mappings dinamici.

### Sincronizzazione configurazioni
- I file JSON vengono creati vuoti (`{"enchantments": []}`) e popolati on-demand.
- `WorldConfigManager.ensurePresentInJson()` aggiunge gli incantesimi quando vengono usati nei comandi o interrogati.

### Supporto JSON5
- I file vengono salvati con estensione `.json5` e sanificati (rimozione commenti e trailing comma) per funzionare con `kotlinx.serialization`.

### Miglioramenti ai comandi
- `/plusec add` e `/plusec remove` accettano ora `RegistryEntry` oltre all'ID stringa tramite `addid`.
- Nuovi fallback tramite `toString()`/riflessione per recuperare l'identificativo degli incantesimi anche con mapping mancanti.
- `/plusec-debug validate` verifica lo stato interno senza cross-check globale.

## ⚠️ Limitazioni note
- I file JSON5 non vengono popolati automaticamente con gli incantesimi vanilla/mod finché non vengono usati.
- L'uso di `/plusec add minecraft:sharpness 3` come stringa può fallire: è consigliato l'autocomplete Brigadier.

## 🔭 Prossimi step pianificati (v1.0.2)
1. Popolamento automatico dei file all'avvio tramite introspezione del registry o `DynamicRegistryManager`.
2. Miglior gestione degli ID stringa (fallback con `Identifier.tryParse`).
3. Sistema di reload live per aggiornare i JSON senza riavviare il server.
4. Estensione dei file di configurazione con metadata aggiuntivi (descrizioni, effetti, tag).
